# 归档政策（archive-policy）

## 原则

**归档先于删除**：任何"疑似无用但不可证明是垃圾"的东西，一律先 `mv` 进 `_archive/<日期>-<阶段>/`
（同盘 rename 秒级、可逆），保留 **30 天**（TTL 政策**单点在本文件**；其余文档只引用，不复述天数）；只有**可证明垃圾**（可再生成的缓存、明确的
临时文件、空目录）才直接删除，且删除前必须留下证明（lsof/模式匹配/引用 grep 输出）。

## manifest 格式（每行一条）

| 列 | 内容 |
|---|---|
| 源路径 | 归档前的原位置（恢复目标） |
| 归档路径 | `_archive/<批次>/<相对路径>` |
| 原因 | 为什么归档（含"可再生成/已被替代/使命完成"判据） |
| 恢复方式 | 恢复命令（通常 `mv` 回源路径）或再生命令 |

## 到期清理程序（2026-10-12 之后执行）

1. **逐行核对 manifest**：对每条归档物回答："这 30 天里有人需要它吗？有没有新证据表明
   它其实是活跃资产？"——不确定的**留到下一期**（默认续期，不默认删除）。
2. 需要保留的 → 移回 `data/`/`projects/` 或转为正式资产（更新 data-map）。
3. 确认可删的 → `rm -rf` 对应归档路径；在 manifest 上标注删除日期。
4. **删除后更新**：唯一事实表是本文件 §"归档批次"（`data-map.md` §D 只放**指针**，
   不再复制表——2026-09-15 R6 消除双写）。
5. 到期程序里的**三个真实决策点**登记在 `pending-items.md` #6（本文件不复制其内容）：
   tick_dev 去留 / minutes-raw 深度血缘 / 备份克隆目录清空。

## 恢复演练（每期至少一次）

从归档区抽 1 件 `mv` 回原位 → 验证可读 → 再 `mv` 回归档。演练记录追加到当批 manifest 末尾。
