## 1. 背景与问题

### 1.1 现状（2026-09-15 实测）

- 算子注册制：注册名 **55 个**（`factorlab op list`）；未知算子直接拒绝（`core/engine/partitions.py:validate_partition_calls`）。
- 库里已装但未接出：polars_ta `wq` 229 + `ta` 68 + `tdx` 167 = 去重 **443 个可调用名**（含少量类型名），其中约 **400 个当前写不出来**（写成公式即报"未知算子"）。
  实测：`ts_quantile`、`BBANDS` 均报未知；`ts_rank`、`ts_zscore`、`ts_corr` 等 55 个可用。
- 加一个新算子 = 改平台 4~6 处（注册表/前缀命名/mask 参数表/窗口解析/测试/活文档）。
- 公式语法层还有绕圈：`&`、`~`、`.fill_null()` 被禁（实测报"不支持的语法节点"/"禁止属性调用"），同一想法要写成嵌套 `if_else`。

### 1.2 用户目标（原话锚定）

> "挖因子的过程会伴随着很多新算子的产生，如果不能表达就会回退到有限的空间，那样就不会产生新因子。"

平台的任务：**让"发明算子"零阻力，而不是审批算子**。

### 1.3 R01 review 的相关发现

- 未来函数门两个旁路（`close[-1]`、常量折叠）——R21 已修（实测 lint 拒绝）。
- 窗口解析只认 `ts_/ta_` 前缀（ENG-I1：累计算子与分块承诺矛盾）。
- `cs_regression_resid` 注册但不可用（NameError）——注册制下的名实不符。
- 文档/注册表/实现三处漂移（catalog、interface、实际行为不一致）。

## 2. 目标与非目标

### 2.1 目标

1. **算子空间开放**：库里全部可用；任意新函数/组合可写，无名单、无前缀、无审批。
2. **算子全生命周期**（用户核心诉求）：就地造 → 提炼命名 → 跨因子复用 → 定档（档案）→ 自动验证 → 算子库累积。
3. **截面表达方案**（§6，建议）：以"通用分组机制 + 少量原语"替代长算子清单。
4. **保证体系**：每个算子（新旧无论）都能回答"在哪算、看多长"；未来函数静态+动态双重保证；准确性自动测试。
5. **兼容**：152 个存量 spec 零迁移。

### 2.2 非目标

- Python 因子脚本为主形态（保持表达式为主；事件/状态型形态见 §11.2 待定）。
- 任意第三方库 import（开放面限定在数据/算子命名空间）。**tick 接口、盘口数据管线**不新建（股票以 bar 为主，盘口为特例）。
- 数据灌入修复、评估口径修复（R01 台账另轮）。
- C++/LLVM 后端实现（只留接口）。
- 矩阵级高级运算（PCA/协方差/约束 WLS/风险模型）——单列模块，不进通用表达层。

## 3. 设计总览

```
用户表达式（任意函数 / 任意组合 / def / 插件）
   │
   ├─ ① 语义推断（每个节点）：
   │     分区（在哪算：按股票 / 按日期 / 按日期×行业 / 逐元素）
   │     窗口（看多长：lookback；是否触碰未来）
   │     ├─ 组合继承：由原语拼出的表达式，语义自动合成
   │     ├─ 自动推断：库函数（polars/polars_ta）预生成分类表
   │     └─ op_meta 声明：黑盒/外部函数，一行补声明
   │
   ├─ ② 编译：分区绑定 → polars 表达式（沿用 expr_codegen 路线）
   │
   └─ ③ 验证：静态门（全形态未来检查）+ 截断重放（分级）+ 新算子 conformance 套件
```

**核心拆分**：把现在焊死在一个概念里的两件事拆开——

| | 现状 | 本设计 |
|---|---|---|
| "算什么" | 注册的算子 | 任意函数/组合（无名单） |
| "在哪算" | 算子名前缀（`ts_/cs_/gp_`）+ 注册 | 分类元数据：推断优先、`op_meta` 兜底 |

## 4. 开放面与关闭面

### 4.1 开放（全部可写）

| 类别 | 范围 |
|---|---|
| 数据列 | 任何数据面真实存在的列（现状已开放） |
| 算子库 | polars 全量、polars_ta `wq/ta/tdx/talib` 全量（当前 443 个可调用名） |
| 自定义 | 公式内 `def`、组合子、插件、`op_meta` 声明的外部函数 |
| 参数 | `${param}`、多输出、`universe.formula`（现状保持） |

### 4.2 仍关闭（保留理由：向量化/安全/语义）

- `eval/exec/open`、文件/网络 IO、`__dunder__` 与未知属性读；
- 循环/递归（向量化保证）；
- 非数据命名空间的第三方 import；
- 引擎内部保留名（`__factorlab_*`、`in_universe` 等）；
- **上下文歧义方法**：`.rank()/.over()/.group_by()` 等——不是名称黑名单，而是语义不明确，报错并指引改用规范形式（`rank(...)`/`by=`）。

### 4.3 验收锚点

`factorlab op list` 从 55 → 400+（库全集可用）；且**任意新函数不因"未注册"被拒**。

## 5. 算子全生命周期（用户核心诉求）

> "注册"从**准入门槛**变为**留档动作**：不是先注册才能用，而是用了、好用了、再定档。

### 5.1 六步

```
① 冒出来   研究过程中需要一个新计算（如"缩量后首次放量"）
② 就地造   公式里直接组合（原语/库函数/def）→ 立刻用于当前因子
③ 提炼     好用 → 给名字、存成算子文件（一个命名算子）→ 跨因子按名复用
④ 定档     算子档案：为什么造 / 怎么用 / 参数 / 验证结果（与因子档案同构）
⑤ 验证     自动 conformance：分区对不对 / 窗口够不够 / 分块是否逐值一致 / 没偷看未来
⑥ 累积     算子库随研究生长（55 → N），全部来自挖矿过程
```

### 5.2 语义（分区/窗口）的三种来源（优先级唯一）

```
def 内联/组合继承  >  库预生成分类表  >  算子档案/manifest  >  spec op_meta  >  报错并给补齐示例
```

- **组合继承**：由原语/已知函数拼出的表达式，分区与窗口自动合成（如 `ts_mean(close,20)→` 按股票、窗口 20；外层再套 `rank(..., by=date) →` 截面）。
- **自动推断**：polars_ta 按命名体系 + 参数签名预生成；polars 方法分类表（脚本生成 + 人工复核清单，测试锁版本）。
  规模实测（Spike 1/2）：polars_ta 三库 **440 个函数（419 个唯一名）**，粗模板冒烟通过 81%（失败多为测试模板参数类型不匹配，真实可用率更高，预计 **350~400**）；polars `Expr` 公开方法 **223 个**（151 逐元素 / 37 窗口 / 35 需人工判定），访问器方法约 212 个（多为逐元素）。分类表生成必须**按签名感知**（不能只看名字前缀）。
- **op_meta 兜底**（仅黑盒/外部函数需要）：

```yaml
op_meta:
  my_roll: {partition: ts, window: ${win}, mask_args: []}
```

### 5.3 算子档案（建议形态）

- 位置：研究树（如 `research/ops/`，最终目录待定）；
- 内容：定义（表达式/参数）+ 语义元数据 + 用途说明 + 验证结果；
- 与因子档案一致：可检索、可版本管理、负结果也可留档。

### 5.4 新算子的三种定义方式与准入

| 方式 | 怎么写 | 作用域 | 语义来源 | 准入 |
|---|---|---|---|---|
| ① 公式内定义 | 组合 / `def`，直接写在因子里 | 当前因子，立即生效 | 组合继承，自动推导 | 随因子跑（静态推断） |
| ② 命名算子 | 研究侧算子文件（带参数） | **跨因子复用** | 自动继承/推断；黑盒补 `op_meta` | conformance 套件通过后入库 |
| ③ 原生/插件算子 | Python 等实现任意算法（含组合不出的，如连续同号游程） | 平台级 | manifest 声明 + 校验 | conformance + 元数据必填 |

- 方式①②为**平台代码零改动**；方式③走一次插件安装（现有 `factorlab op add` 保留，增元数据要求），同样不改平台源码。
- **conformance 套件**（准入即测试）：分区正确性 / 窗口充分性 / mask 行为 / 分块与整段逐值一致 / 小样本逐日截断因果探测（Spike 3 方法）。
- 带内部状态的算法可作为方式③实现（状态封装在算子内，对外仍是普通函数）；与 §11.2 "因子级事件形态"是两回事。

## 6. 截面表达方案（建议，待评审）

> 调研结论：业界"截面算子清单"（WQ BRAIN 98 个、米筐 `CS_` 系列等）拆开看全部是
> **少量原语 + 分组机制**的组合；Quantopian Pipeline 更进一步——截面变换是"任意表达式 +
> 指定分组"的通用方法，不存在 `cs_rank` 这类独立算子。本平台采取同一路线。

### 6.1 一个分组机制（`by`）

三种分区是同一机制的三个实例：

| 分区 | 分组键 | 组内序 | 现状算子对应 |
|---|---|---|---|
| 时序（ts） | 股票 | 日期 | `ts_*` |
| 截面（cs） | 日期 | 无 | `cs_*` |
| 分组截面（gp） | 日期 × 分组键（行业/桶…） | 无 | `gp_*` |

### 6.2 原语（7 个 + 时序基座）

| 原语 | 语义 | 组合出 |
|---|---|---|
| `agg` | 组内归约：mean/std/median/mad/sum/count/min/max/quantile | 一切组内统计 |
| `rank` | 组内排名（可百分比、并列策略） | cs_rank / group_rank / topN |
| `clip` | 截断极端值 | 三种去极值（σ / MAD / 分位） |
| `cut` | 连续值 → 桶标签 | 分层、双重排序的分组键 |
| `dist` | 排名 → 分布映射（正态等） | rank-normal |
| `proj` | 组内回归取残差（单列=正交化；多列=多元中性化） | 行业/市值/风格中性化 |
| `mask` | 空值/股票池/停牌/涨跌停（一等公民） | A股"谁参与计算" |
| （时序基座）`rolling/shift` | 按股票、有序、带窗口 | 与时序正交 |

### 6.3 组合映射（存量算子的表达方式）

```
cs_rank(x)              → rank(x, by=日期)
cs_zscore(x)            → (x − agg(mean, by=日期)) / agg(std, by=日期)
group_rank(x, 行业)     → rank(x, by=[日期, 行业])
行业内中性化            → x − agg(mean, by=[日期, 行业])
行业+市值中性化         → proj(x; 行业 + log市值)     ← 唯一不能只用分组拼的操作
winsorize(x)            → clip(x, agg(mean±kσ, by=日期))
ts_mean(close, 20)      → agg(mean, by=股票, order=日期, window=20)
```

### 6.4 A股语义（必须与方案同批落地）

- **掩码独立于数值**：ST / 停牌 / 上市未满 N 天 / 涨跌停分别出布尔列，先筛再算（不靠 NaN 隐式表达）；
- **PIT**：行业分类、财报、指数成分按公告日快照（行业分类会被回溯修订，用最新映射算历史 = 前视）；
- **组内样本不足**：`min_count` 保护（小行业不硬算）；
- **空值语义**：默认不参与计算、输出仍为空；填充操作显式写。

### 6.5 静态推断（取代白名单的保证机制）

自底向上为每个节点推断：

```
{ level: 逐元素|cs|ts|gp, keys, order, lookback, forward(必须为0), window_safe }
```

- 未来禁止：任何产生 `forward > 0` 的调用拒绝（推广现有 `reject_future_shifts`）；
- 组键合法性：`by=` 的键必须是逐元素级（不得含未聚合的 ts/cs 结果）；
- 窗口可加性：`lookback(f∘g) = lookback(f)+lookback(g)` → 供分块/预热自动推导。

## 7. 保证体系

### 7.1 未来函数

| 层 | 机制 | 状态 |
|---|---|---|
| 静态 | 负位移/负下标/负窗/方法 `.shift(-1)`/常量折叠全形态；未来列名前缀；R21 已修的两个旁路收编进统一规则 | 规则已定 |
| 动态 | **截断重放**（Spike 3 实测见 §13） | **定位修正**：重放不能当因子级保证——每个截断点只能检出它之前 k 天（k=泄漏跨度）的泄漏，远离截断点的局部泄漏抓不到。正确用法：① **算子准入 conformance 用小样本密集截断**（逐日截断、小样本，因样本小所以便宜）；② 因子级抽样重放仅作冒烟（抓系统性泄漏）；③ 主保证仍是静态推断；黑盒算子的局部泄漏残余风险明确写入活文档 |

### 7.2 准确性

- 分区必答：推断不出且未声明 → 拒绝编译（消灭"裸名元素级"静默跨资产泄漏）；
- 窗口必答：自动推导预热；`unbounded`（累计算子）与分块互斥 fail fast；
- **新算子 conformance 套件**（准入即测试）：分区/窗口/mask/分块逐值一致/截断重放 全部通过才算可用；
- 数据可用性检查：声明输入 → 跑前检查（日期范围 × 标的范围）覆盖；缺数据明确报错（不装空值）；
- 文档同源：`catalog` 由分类元数据生成（防漂移）。

## 8. 兼容与迁移

### 8.1 零迁移承诺

152 个存量 spec 全部是"无状态表达式 + 已知算子"的子集：`ts_/cs_/gp_` 前缀降为**语法糖**，内部统一降级为 `(分组键, 组内序, 窗口)` 模型，行为逐值不变（抽样价值级回归）。

### 8.2 三阶段

1. **阶段 1（兼容）**：前缀分类器保留；引擎内部统一到 `(level, keys, order, window)`；补齐窗口推断与未来检查（R21 的修复收编）。
2. **阶段 2（开放）**：库函数分类表全量生成（polars/polars_ta）；算子名自由（`rank` 不必叫 `cs_rank`）；显式 `by=`；`op_meta`；算子档案与自动验证。
3. **阶段 3（生态）**：插件/外部函数接入同一语义体系；算子库检索与复用。

## 10. 验收标准

1. `factorlab op list` ≥ 350（以分类表与 conformance 通过为准）；任意 polars/polars_ta 函数写入公式不再报"未知算子"；
2. 新旧旁路（`close[-1]`、常量折叠、方法负位移、负窗）全部被拒；
3. 新算子：造→用→复用→档案→自动验证 全流程可用，平台代码零改动；
4. 截断重放：正例通过、故意未来函数被抓；
5. 分块与整段逐值一致（全部算子类别）；
6. 152 spec 零迁移，lint 152/152，抽样价值级回归通过；
7. `make gates` / 平台全量测试 / 研究测试全绿，性能不退化。

## 13. 验证性 Spike 结果（2026-09-15 实测，结论已回写 §5.2/§7.1/§9/§10）

三个一次性原型实验（脚本在 `/tmp`，未入库；方法可复跑）。目的：验证方案最关键的三段未知。

### Spike 1：算子库存与冒烟可用率

| 库 | 函数数 | 前缀分布 | 粗模板冒烟通过 |
|---|---|---|---|
| wq | 205 | ts_ 67 / cs_ 30 / 无前缀 108 | 91% |
| ta | 68 | ts_ 44 / UPPER 24 | 76% |
| tdx | 167 | ts_ 133 / UPPER 34 | 72% |
| 合计 | **440（419 唯一名）** | — | **81%（358/440）** |

失败归因：48 AttributeError + 9 TypeError 多为**测试模板参数类型不匹配**（如 `ta.ts_AROON` 收到 int、实际需 Expr），非算子缺陷；15 RuntimeError（ta 线性回归族等包装异常）、9 ComputeError（horizontal 族需多列）、少量辅助函数（lit/when/struct）。
**结论**：真实可用率高于 81%，预计 **350~400**；分类表必须按签名生成调用模板（不能只看名字前缀），并配少量淘汰清单。

### Spike 2：polars 方法面与可分类性

- `pl.Expr` 公开方法 **223 个**：151 逐元素 / 37 窗口 / **35 需人工判定**（`over/group_by/sort/filter/rank/gather` 等——设计上应拒绝或指引）；
- 访问器方法：`.dt` 47、`.str` 49、`.list` 43、`.arr` 32、`.struct` 6、`.cat` 8、`.name` 10、`.meta` 17（多为逐元素）。
**结论**：分类可自动化 + 约 35 个方法的人工清单；版本锁测试防 polars 升级漂移。

### Spike 3：截断重放（关键发现）

合成面板 300 股 × 500 天，3 个截断点：

| 因子 | 检出结果 |
|---|---|
| 正常因子（20 日均线） | 3 个截断点全部 **0 不一致**（无误报，逐值相等） |
| 泄漏 `shift(-1)` | 每个截断点精确检出 **300 行 = 截断点当天** |
| 泄漏 `shift(-20)` | 检出截断点前 **20 天 × 300 股** |
| 局部泄漏（仅 6 月，远离 10 月/3 月两个截断点） | **两个截断点都抓不到** |

成本：单次截断重算 ≈ 全量一次；K 个截断点 ≈ **(K+1)×** 成本。

**结论（修正 §7.1）**：截断重放 = "截断点前 k 天的边界窗口检查"，**不能作为任意代码的完备保证**。正确用法：
1. **算子准入 conformance 用小样本密集截断**（逐日截断、小样本，样本小所以便宜）——验证新算子的声明窗口/因果性；
2. 因子级抽样重放仅作冒烟（抓系统性泄漏）；
3. 主保证仍是**静态推断**；黑盒算子的局部泄漏残余风险写入活文档。
