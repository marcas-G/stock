# FactorLab 挖因子 Skill 设计文档

日期：2026-08-17
状态：待评审
前置：M1-M5 + 自由代码公式 + 因子档案体系（`docs/factors/`）

## 1. 背景与目标

用户希望有一个**挖因子的自动化 skill**：以因子库中现有因子为种子，分析其假设、
审核假设、在种子基础上变异假设、实现新因子、审核、跑结果、按模板入库，循环执行。

**核心目标**：
1. **变异衍生（隐含假设精确化）**：因子实现的每个选择背后都有一个**隐含假设**
   （为什么 20 日？为什么等权？为什么对所有股票同质？为什么用 close？）。
   挖因子 = 把这些没被关注到的隐含假设显式化、审核、在种子的假设集合上
   变异/精确化，产出一个**更详细准确**的因子表达——**不一定增加表达式深度**。
2. **自动循环**：一次调用连续执行 N 轮，每轮独立完整（种子→实现→跑→入库），
   用户随时可中断。
3. **可归因**：变异点明确记录，新因子结果优劣可追溯到具体假设。
4. **负结果也入库**：无效变异同样是假设空间的探索记录。

**边界**（用户确认）：
- 假设分析**不强制分类**（不限制市场/数据/表达三类框），自由分析、创造力为主。
- 变异**只能在种子因子的假设集合上**变异/组合，可一次变异多个假设，
  不引入与种子无关的全新假设。
- **创新点在隐含假设上**：改进的是"原有因子隐含假设的表达精度"，
  不是加深公式复杂度、也不是外部引入新方向。
- 结构变异 = 新 spec 文件（非 `--set` 参数变体）。

## 2. Skill 形态

项目级 skill（`/factor-mine` 调用），不依赖插件：

```
.claude/skills/factor-mine/
  SKILL.md                 # 主指令：流程 + 规则（本文 §3-5）
  assumption-review.md     # 假设分析与审核工作模板（自由式引导）
  code-review.md           # subagent 代码审核提示词
```

调用：`/factor-mine [N]`，N 为轮数（默认 1）；连续 N 轮，轮间不停顿、可中断。

## 3. 每轮流程（8 步）

```
1. 种子选择   docs/factors/*.md 随机选一个（连续轮次互不重复）
2. 假设分析   自由分析种子因子的隐含假设（不分类，创造力为主）：
              枚举每个实现选择背后的隐含假设——窗口长度/口径/权重/股票同质性/
              数据字段/调仓频率/处理链……每一个"为什么"都是一条隐含假设；
              重点是那些通常没人显式关注的（其实有很多）
3. 假设审核   对每个隐含假设判定 成立/可疑/证伪/可精确化：
              · 语义矛盾：假设间互斥？与平台语义冲突（TS/CS 分区、防未来、方向）？
              · 数据可实现：字段存在性（interface.md + 库 schema 核对）、
                窗口 vs 历史（数据自 2000-01-04）、缺失率预估
              · 证据：种子档案验证数据（IC/分层/近 26 周）+ 已知异象知识
4. 变异设计   在种子假设集合上变异/组合（可多个；目标是隐含假设的
              显式化与精确化——更详细准确的因子表达，不追求表达式深度）：
              · 保留哪些假设、精确化/变异哪些、变异成什么、为什么
              · 变异后假设集合的语义一致性（重新过一遍 §3 矛盾检查）
              · 新因子名 <seed>_<variant>
5. 实现       写 factor/<name>.yaml + 语义↔代码映射表（每条变异语义→公式行）
              · 沿用平台自由代码公式表达（def/参数化）
6. 代码审核   独立 subagent（code-review.md 提示词）：
              · 语义↔代码对齐、防未来、TS/CS 分区正确
              · 变异点之外与种子因子逻辑一致（只该变的变了）
7. 运行       factorlab run factor/<name>.yaml；失败修复重跑
8. 入库       对照 factor-mining-playbook §4.1 阈值判定 →
              docs/factors/<name>.md（_template.md 模板，验证数据快照）→
              种子档案 §5 迭代历史加一行 → 互相链接 → git 提交
```

## 4. 关键规则

| 规则 | 内容 |
|------|------|
| 隐含假设优先 | 挖点是"没被关注到的隐含假设"——改进表达精度，不加深公式复杂度 |
| 聚焦变异 | 变异限于种子假设集合；可多个；不引入无关新假设 |
| 可归因 | 变异点逐一记录，结果优劣回溯到具体假设 |
| 负结果入库 | 不显著也建档案（判定"无效/证伪"），种子档案同样记录 |
| 审核分工 | 假设审核主 agent 做；代码审核独立 subagent（§2 code-review.md） |
| 种子不重复 | 同一批连续轮次内种子互异；跨批次可重复（变异方向不同） |
| 新 spec | 结构变异不用 --set；--set 仅用于同结构参数扫描（迭代历史记录） |
| 状态 | 新因子档案 status 按阈值判定（候选/观察中/无效） |
| 资源 | 每轮 ~1 次全市场 run（30-60s）+ 2 个 subagent；results/ 每轮数十 MB；16GB 内存护栏不变 |

## 5. 测试策略

Skill 为流程指令文档 + 模板文件，验证方式：

- **演练验证**：执行 `/factor-mine 1` 一轮端到端，验证 8 步全部走通、
  产出（新因子 yaml + 档案 + 种子档案互链 + 提交）符合本设计；
  修复流程文档暴露出的缺口。
- **模板检查**：assumption-review.md / code-review.md 内容与 SKILL.md 引用一致。
- **防回归**：平台现有测试全量通过（skill 本身不改平台代码；
  演练产出的新因子档案/YAML 不破坏现有约定）。

## 6. 明确不做

- 不引入种子无关的全新假设方向（用户确认边界）。
- 不做因子有效性自动增强（如自动参数扫描循环——那是研究职责，`--set` 手动）。
- 不改平台代码（skill 纯流程/提示词；若演练暴露平台缺口，另开 spec）。
- 不做多因子组合（已明确不属于平台）。
