## 1. DSL 形态总述

> 全局框架：平台 = 多层漏斗（§8）——模板总是绑定到**某一层的数据接口**上计算。
> 本规格的模板/接口/条件规则与时间尺度无关，对任一未来层原样适用；
> M1–M5 落地 Interface #1（日频 + 属性）。

DSL（模板语言）= **受限 Python 子集**，写在 FactorSpec 的字段里（`formula`、未来 `universe.formula`），
语法层是普通 Python（def / 中间变量 / 常量 / 注释 / 方法链 / 关键字参数 / import 别名），
编译器（静态 AST 门 + expr_codegen 代码生成）在真正执行前接管：

1. **未来函数门**：任何"引用尚未发生数据"的写法在执行前静态拒绝（详见 §5.3）；
   含绕道形态（命名常量间接、import 别名）。逐条带 `行:列` 报错。
2. **向量化保证**：def/结构展开成 polars 整表表达式，无逐行 Python 循环；
   分区语义（ts_ 按股票自身历史 / cs_ 按同一时刻横截面 / gp_ 按分组）编译期锁定。
3. **确定性**：同公式 + 同数据 ⇒ 同结果。
4. **开放面（修订后）**：数据与算子全开放——任何真实存在的列可直接引用、
   def 内联定义新算子（任意组合窗口/截面/分组/元素级）、顶层赋值定义新字段。
5. **关闭面（仅三类，均为目的的投影）**：①无法向量化或不可控的语法
   （循环/递归/属性访问/未知调用）；②未来数据引用（负位移、未来数据类别列名）；
   ③内部保留列名。拒绝即报错，带 `行:列`，文案自解释——AI 照报错改一轮即过。

## 3. 定稿语义 ①：多信号输出

### 3.1 语法与命名

- 语法**零改动**：公式仍是自由 Python 子集，任一顶层赋值产生一个命名列（与现状一致）。
- 输出声明移到 spec 层，向后兼容：
  ```yaml
  formula: |
    _mom = close / ts_delay(close, 1) - 1
    signal = ts_mean(_mom, 5)
    signal_vol = ts_std(_mom, 20)
  outputs: [signal, signal_vol]     # 缺省 = [signal]（完全兼容现有 spec）
  ```
- `outputs` 每个名字必须（a）匹配 `NAME_PATTERN`，（b）在公式中实际产生该列，
  （c）不是内部保留名（`__factorlab_*`、`in_universe`、`forward_*`、`future_*`、`target`、`label`），
  （d）**全局唯一**（复核点 2 定案：重名 → 报错指认冲突）。
- `signal=` 单输出 spec（不写 `outputs`）行为与今天逐字节一致。

### 3.2 运行语义

- **一趟计算**：所有输出共享同一次 `compute_formula` 向量化 pass（公共中间量只算一次——
  多输出 = 效率目的的直接落点）。`compute.py:107`"必须含 signal + 只保留 signal"
  改为"必须含 outputs 全部声明的列，按 outputs 保留"。
- **每个输出独立走下游**：per-output process 链、label 计算、artifact 落盘、评估/回测
  入口各自独立。
- `FactorResult.panel` 保留全列；`signal_artifact` 系列按输出名粒度产出；
  `summary` 增加 per-output 指标块。
- `factors+combine` 维持现状（`NotImplementedError`）——多输出是**并列输出**，
  combine 是**加权合成**，语义不同；本定稿不替 combine 背书。

### 3.3 档案/回测交互（语义声明）

研究档案按输出名 1:1 落库（factor/、results/、docs/factors/，research 侧）；
平台侧 `write_factor_artifacts` 支持按输出名产出（`<spec.name>__<output>`）。

## 4. 定稿语义 ②：股票池完全由公式决定

### 4.1 分层模型

股票池 = **上市骨架（数据存在性层）∩ 公式池条件（成员资格层）**：

1. **骨架层（沿用现状，不可由公式表达）**：PIT listed skeleton、交易日历、停牌补全行。
   它不是"选股"是"数据存在性"——公式写不到它。
2. **成员资格层（新增，公式全权）**：`universe.formula` = 布尔表达式，逐 (code, 交易日)
   判定池内/池外。池不依赖静态 codes/rules/ref（四选一互斥，复核点 1 定案）。

```yaml
universe:
  formula: close > ts_mean(close, 60)   # 池 = 收盘价站上 60 日均线（逐日动态）
```

### 4.2 求值语义（无自指、无循环依赖）

- 池公式与主公式**同一条门链、同一开放数据面**（§5），额外要求**布尔可判定**
  （存在比较/布尔运算且结果列 dtype 为 Bool；否则报错）。
- 池公式在**完整上市骨架**上求值（不套 universe mask）：
  - TS 算子：逐股票完整历史（listing 先行，与主公式 TS 同语义）；
  - CS 算子：**全骨架当日横截面**（含暂不满足池条件的股票）——骨架先于条件已知，
    无自指；"相对全市场强度"条件（如 `close > cs_median(close)`）由此可表达；
  - GP 算子：**第一版开放**（复核点 3 定案），分组键 = 开放数据面中的 per-code
    属性（如 `industry`，§5.2）——行业属性独立于池条件，组内截面在完整骨架的
    同行业内求值，无自指；"行业内相对强弱"（`gp_rank(ts_delta(close,5)) > 0.9`）
    可表达。属性为空的股票不进任何组：组内统计不含它，依赖组统计的条件对它不成立
    （可写 `industry != null` 类条件显式处理）。
- 求值顺序锁：骨架 →（fill → view）→ **池公式** → `in_universe = 骨架 ∧ 池条件`
  → 主公式以 `__factorlab_universe_active = in_universe` 作 mask 求值
  （机制不变，`compute.py:374-380` 只把 mask 来源从"静态规则"换成"池公式结果列"）。
- 时序语义：池条件用当日及以前数据（同主公式，未来门同一条链），成员资格 t 收盘已知、
  t+1 可交易——与主信号时点一致，无额外未来泄漏面。

### 4.3 spec 模型增量

- `UniverseSpec` 增加 `formula: str | None` 分支，`_exactly_one_universe` 扩为
  ref/codes/rules/formula **四选一互斥**（复核点 1 定案）。
  需要"名单 ∧ 条件"（沪深300成分 ∧ 站上均线）：名单经数据面以**成分标志字段**
  （per-code 0/1 属性，§5.2 同机制）进入公式——不设第二个 spec 来源。
- codes/ref 仍可作 dry-run 白名单（RunContext.universe_override 语义不变，仅限骨架）。

### 4.4 主公式 CS 语义不变式（必须守住）

主公式 CS/GP 只见 `in_universe`（=动态池）当日横截面——与现状"只见 active 横截面"
机制一致；动态池只是改变 active 集合。回归网须含：**同一股票在池内/池外两种状态的
CS 因子值互不一致且池外不参与截面**（锁语义，防实现漂回全骨架）。

## 5. 定稿语义 ③（修订版，覆盖 2026-09-06 初答"受控注册制"）：数据与算子全开放

> 用户二次答复原话："这个不自由了，应该支持内联函数定义新的算子和字段定义，
> 所有的数据都应该开放。"
>
> **修订核心：不设字段白名单、不设算子白名单。目录（catalog）从"校验门"
> 降级为"活文档 + 报错助手"。关闭面只剩三类——它们正是用户定义的两个目的
> （计算效率、未来函数限制）本身的投影，不是自由度削减。**

### 5.1 开放面（全部自由，无登记要求）

- **数据列全开放**：公式可引用任何数据源**真实存在**的列。
  - daily 表任意列：读路径本就按公式引用列拉取（`_formula_columns` → `load_daily(cols=)`），
    现状即自由，无需任何登记；
  - per-code 属性（industry、成分标志…）与日期标志（停牌等）：**开放解析器**
    （§5.2）自动定位来源并 join——"存在即可写"；
  - 未来新数据表接入 = 给解析器加一个来源（读路径能力），**不是注册流程**。
- **新算子靠 def 内联定义**（现状机制，本规格确认并文档化）：def 可嵌套、可组合
  elementwise/ts_/cs_/gp_/ta_ 任意已有算子、可含方法链；执行前 `inline_defs`
  展开成顶层 ts_/cs_/gp_ 调用（A2/A3 组合形态已验证真算）。**def 即"新算子工厂"**，
  无数量/命名/登记限制。
- **新字段靠顶层赋值定义**：任一命名赋值即派生字段，可被后续行引用、可声明为输出
  （§3）。字段名无保留列表之外的限制。
- registry 只是**平台自带算子的实现登记**，不构成写入门槛。

### 5.2 开放解析器（新能力，M3 落地；接口化预留）

公式引用列 → 解析器按来源解析并组装数据面（duckdb|ch 各编译函数对）。
本阶段实现 **Interface #1**：

1. daily 表列（现路径）；
2. per-code 属性（静态/低频，如 industry、成分标志）：按需从 stock_basic 等 join；
3. （后续按需扩展：停牌标志等日期级来源、**下层漏斗层上抛列**——§8 层间耦合通道；
   1m/tick 接口的读取已存在（M3 交付），成为模板接口属后续里程碑）。

引用无法供给的列 → **报错助手**：列出**当前数据面实际可用列** + 最相似候选名
（编辑距离 ≤ 2）+ 指向活文档。**帮助而非拦截**——列真实存在即自由可写。
解析器与活文档共享同一 schema 元数据（防漂移）。

### 5.3 关闭面（仅三类，均为目的投影，与"自由"不冲突）

1. **语法/效率门**（计算效率目的）：循环、递归、任意属性访问、未知调用——
   无法向量化或不可控 → 静态拒绝（既有 partitions 门，不因自由度放开）。
   def 内窗口算子的安全网保留（`validate_partition_calls` guard：未内联的 def 内
   ts_/cs_ 调用会当黑盒全表开窗、跨资产泄漏；内联后自动合法——守卫只在
   直接路径触发）。
2. **未来函数门**（未来函数限制目的）：
   - `ts_delay/ts_delta` 负位移三类形态静态拒绝（字面量/顶层常量赋值/import 别名，
     fd7967f）；
   - **未来数据类别列名**：`forward_*`/`future_*`/`target`/`label` 前缀在因子公式
     中拒绝（`_check_future_inputs`）。**数据侧纪律：凡是内容含未来信息的表列，
     命名必须落在这类前缀下**——约定进活文档与数据入库校验；这样"数据全开放"
     不会把未来数据漏进公式。真正的"墙"是名字类，不是字段白名单。
3. **内部保留列**：`__factorlab_*`、`in_universe`（引擎语义依赖，用户不得定义/引用，
   引用即报错）。

### 5.4 活文档（决策④，事无巨细）

- 描述**开放面**：现有字段语义/单位/产生时点、算子用法/参数/约束、def 组合规范与
  示例、命名类约定（含"未来列必须落未来前缀"纪律）、错误与修法手册；
- 描述**关闭面**：每条门规则 + 触发示例 + 报错文案样板（门表 ↔ 测试逐条对照）；
- 机器可读 JSON（`catalog dump` 入口）同源生成，供写因子的 AI 开写前阅读。
- 文档 = 教学与帮助，不是许可证。`docs/interface.md` 只写已实现行为，不超前。

## 8. 多层漏斗架构图景（用户 2026-09-07 补充，全局框架）

> 用户原话："应该是有多层，每层的时间尺度是不一样的，像是一个多层漏斗，我们在
> 不同级别进行因子挖掘，然后使用模型对因子进行聚合，进行过滤，这就是每层的工作方式。"

### 8.1 图景

平台按**时间尺度分层**（tick → 1 分钟 → 日 → 更低频…，尺度集合随数据接入扩展）。
每一层的工作方式相同：

1. **数据接口**：该层时间尺度的全部数据（含下层上抛的产出）；
2. **因子挖掘**：大量模板（结构/参数网格）套在本层接口上计算候选因子；
3. **模型聚合**：把本层候选因子聚合成少数强信号；
4. **过滤**：按评估标准留下强的、淘汰弱的；
5. **上抛**：本层产出成为**上一层数据接口的输入列**。

层间耦合只有一个通道：**下层产出 = 上层接口的列**（如 tick 层挖出的微观质量因子
聚合成日度值 → 日频层把该列当作每股票每日属性引用）。这正是 §5.2"per-code 属性"
机制的放大形态——上层接口不是"全部重读"，而是包含本层字段 + 下层上抛列。

### 8.2 工程边界（平台 vs 研究）

| 职责 | 归属 |
|------|------|
| 每层的数据接口供给（读路径/解析器/接口化绑定） | **平台**（本仓库，本规格） |
| 模板计算 + 计算中条件保证（未来函数/分区/向量化） | **平台**——条件保证与时间尺度无关，任何层同一套门与分区语义 |
| 层内聚合（模型/权重）、过滤标准、挖掘编排（模板网格/搜索） | **研究侧**（消费平台算出的因子档案；平台既有 `factors+combine` 模型维持 `NotImplementedError`，不替研究侧模型背书） |
| 层间上抛（下层产出写入上层接口） | 产出的落库与研究编排（研究侧） + 上层接口的供给（平台读路径，按新接口注册） |

### 8.3 对本规格的影响

- **接口是头等概念**：模板绑定到"数据接口"运行（名称空间 = 接口提供什么列）。
  本计划 M1–M5 只落地 **Interface #1 = 日频行情 + per-code 属性**，但绑定/解析器
  按接口化设计，不把 daily 硬编码进模板语义——bars_1m/tick 读取接口已存在
  （M3 交付，ch 后端），是候选 Interface #2/#3 的数据基础，接入方式 = 按 §5.2
  给解析器加来源 + 接口注册，条件保证不变。
- **每层的条件保证相同**：未来函数门、分区语义、向量化与时间尺度无关——
  本规格 §1/§4/§5 的一切规则对任一未来层原样适用。
- **时点语义随层细化**：层越小，接口列的"产生时点"越精确（tick 层某时刻才知道的
  值上抛到日层是日末已知）——属性列登记的产生时点字段承担此语义（§5.4 的
  industry 近似是首例，下层产出列同样带时点登记）。
- **规模**：1m 1.85B 行/tick 9.95B 行——分钟层模板计算需分块与资源护栏，属后续
  接口里程碑的设计内容，不在 M1–M5。

### 8.4 因子分层与管理系统（用户 2026-09-07 补充）

> 原话："产出的因子，应该有管理系统管理；因子是分层的；因子虽然本身有筛选作用，
> 但是很少这样使用，会经过一些模型进行信号的聚合。"

- **因子分层**：每个产出因子带**漏斗层标识**（tick/1m/日/…）与**血缘**——层间上抛
  即因子层级：下层聚合列被上层模板引用时，上层因子是下层因子的子节点。
- **管理系统（因子库 registry）**：管理每个产出因子：
  - 身份：spec 名 + output 名 + 参数快照（版本）；
  - 层标识与血缘（父因子/输入下层产出列）；
  - 评估结果关联（既有评估流水线产物按因子版本挂接）；
  - 状态（活跃/退役）。
  - 查询能力：按层列因子、按血缘追溯、**多因子对齐面板导出**（同一 date/code 网格
    多因子并排——模型聚合的直接输入形态）。
- **消费模式**：单因子直接当筛选器 = 少数路径（`universe.formula` 引用因子输出即此
  用法，保留）；**主流 = 模型把多因子聚合为信号**（研究侧模型），聚合信号可再作为
  上层因子注册回系统——漏斗闭合。
- **工程边界**：管理系统代码/API 属平台（src/factorlab 新模块 + 查询入口，G7）；
  因子档案数据与研究编排属 research（分支纪律沿用）。G7 为 M1–M5 之后的独立里程碑，
  但 **M2 落 artifacts 时即预留元数据钩子**（输出名/层标识/血缘可挂字段），防回改。
